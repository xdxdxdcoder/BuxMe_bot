# Buxme AI-Scout

Buxme AI-Scout помогает менеджеру по развитию Buxme находить потенциальных оптовых партнёров по региону. Основной сценарий: открыть выданного бота в MAX, запустить мини-приложение, ввести демонстрационный код сотрудника, найти компании, изучить факты, источник, приоритет проверки и доступные контакты. Наличие нужного ассортимента и интереса к сотрудничеству подтверждается разговором, а не индексом.

- Бот: [@t519_hakaton_max_bot](https://max.ru/t519_hakaton_max_bot).
- Текущий публичный адрес: <https://bux-me-bot.vercel.app/>. Доступность с российских IP и внутри MAX требует отдельной проверки; ответ из зарубежной сети её не подтверждает.
- Код для демонстрационного входа: `BUX-2048`. Это проверка формата, не реальная авторизация сотрудника.
- API: `POST https://bux-me-bot.vercel.app/api/scout/search`, [описание OpenAPI 3.1](openapi.yaml) и [конфигурация проверок DATA-API](DATA-API.yaml). Рабочие секреты в репозитории отсутствуют.

Каталог `backend/data/fns_sme_20260910.json` содержит 3297 субъектов по 86 территориям. В нём могут отсутствовать записи для отдельных регионов и городов. Для повторной сборки выборки используется `scripts/build_fns_catalog.py`; перед обновлением нужно проверить выпуск и контрольные суммы архивов. Публичные контакты проверены по страницам [МЕЙТАН](https://meitanglobal.com/contacts/), [ParisNail](https://parisnail.ru/contacts.html) (на странице указан ИНН 7806577036) и [ART&FACT](https://art-fact-products.com/contacts/) (ИНН 9715397054 указан в [оферте](https://art-fact-products.com/oferta/)). Данные источников и даты видны в интерфейсе.

## Архитектура

- `src/`: React 19, TypeScript, Vite, адаптивный интерфейс, MAX Bridge. `VITE_APP_MODE=live` направляет поиск в HTTP API. Демо-режим с синтетическими карточками доступен отдельно.
- `api/scout/search.py`: FastAPI поиска, пагинация, контракт карточек, оценка по фактам и необязательный GigaChat. Основной поиск по локальной выборке ФНС выполняется непосредственно в функции без прогрева внешнего сервера.
- `api/auth/max.py`: демонстрационный вход. `api/max/webhook.py` и `server/`: приём событий MAX и кнопка `open_app`.
- `backend/parser.py`: чтение подготовленного каталога; старый режим Rusprofile существует для разработки, но не нужен для основного сценария.
- `nginx.conf`: отдача Mini App и прокси API в Docker.

В репозитории два зафиксированных набора зависимостей: `pnpm-lock.yaml` для frontend и `requirements.txt` for Python (`requirements.legacy.txt` only for the unused Rusprofile developer mode) для Python. Внешние сервисы: MAX Bot API и Bridge, открытые данные ФНС, необязательный GigaChat. Рабочие токены MAX и GigaChat необходимо задавать только через переменные сервера.

## Одна команда запуска через Docker

Нужны Docker Engine и Compose. Из корня репозитория:

```bash
docker compose up --build
```

Команда запускает frontend, API поиска и webhook. Сайт доступен на `http://localhost:8080`, API внутри сети Compose — порт `8000`, webhook — порт `8001`. Для локальной проверки основного поиска секреты не нужны: без ключа GigaChat API использует расчёт по фактам. Для реальной доставки webhook задайте `BOT_TOKEN` и `MAX_WEBHOOK_SECRET` в локальном `.env` (образец `.env.example`, без секретов). Docker Compose автоматически подхватит `.env`. При локальном запуске бот не подключится к `localhost`: MAX требует общедоступный HTTPS-адрес webhook и привязанного Mini App.

Проверка API без входа:

```bash
curl -X POST http://localhost:8080/api/scout/search -H 'Content-Type: application/json' -d '{"region":"Москва","limit":1}'
```

Ожидается `200`, `mode: registry`, непустой `companies`, дата `sourceDate`, `scoringMode: factual` без ключа GigaChat. Для интерфейса войдите с `BUX-2048`, найдите «Алтайский край», откройте ООО «МЕЙТАН»: отображаются публичный телефон, сайт, ссылка на первоисточник и кнопка поиска контактов. Откройте любую другую карточку: неподтверждённый телефон не придуман, доступен поиск по названию и ИНН.

Остановка: `docker compose down`. Повторный запуск: `docker compose up --build`. Данные избранного и статусов остаются в хранилище браузера, а не в контейнерах.

## Переменные окружения

Полный список и безопасные примеры — в [.env.example](.env.example).

| Переменная | Назначение |
| --- | --- |
| `VITE_APP_MODE=live` | Режим frontend на этапе сборки (`mock` только для синтетического демо). Значения `VITE_*` публичны. |
| `VITE_RUNTIME_MODE` | Приоритетный override режима для старого Vercel-проекта. |
| `VITE_API_BASE_URL` | Базовый адрес API при раздельном размещении. В Docker пустой: запросы идут через Nginx. |
| `BOT_TOKEN`, `MAX_WEBHOOK_SECRET` | Секреты MAX Bot API и webhook; обязательны только для живого бота. |
| `MAX_BOT_USERNAME`, `MINI_APP_URL` | Имя выданного бота и публичный адрес Mini App. Административную привязку выполняют организаторы. |
| `GIGACHAT_API_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` | Необязательная AI-оценка. Ключ только на сервере. |
| `SCOUT_DATA_SOURCE` | `fns` для основного сценария. |
| `SCOUT_BACKEND_URL` | Старый прокси для неосновных режимов поиска; при `fns` не используется. |

## Публикация и проверка в MAX

Публичный сайт требует HTTPS и постоянной доступности из РФ. Если домен `.vercel.app` не отвечает с российского IP, переносите тот же Docker-стек на доступный из России хостинг с HTTPS. Пример для VPS с собственным доменом: `APP_DOMAIN=ваш-домен docker compose -f compose.yaml -f compose.production.yaml up -d --build`. Для него DNS A-запись должна указывать на VPS, порты 80/443 должны быть открыты; Caddy выпустит сертификат. Сам домен и хостинг не предоставляются этим репозиторием. После смены адреса отправьте новый HTTPS URL организаторам через [форму привязки мини-приложения](https://sbor-ssylok-dlya-mini-prilojeniy.testograf.ru/); участникам не следует менять административные настройки выданного бота. Обновите адрес API в `DATA-API.yaml` и адрес в материалах сдачи. Локальная проверка не заменяет тест в мобильном и веб-клиенте MAX.

Порядок проверки опубликованной версии:

1. Из российской сети откройте HTTPS URL и проверьте `POST /api/scout/search` с `Москва`.
2. В MAX откройте [бота](https://max.ru/t519_hakaton_max_bot), отправьте `/start`, нажмите «Открыть AI-Scout».
3. Введите `BUX-2048`, найдите «Алтайский край», откройте карточку и проверьте контакт, источник и пометку расчёта.
4. Повторите в мобильном и веб-клиенте MAX. Убедитесь, что путь открытия, вход, поиск, карточка и переход по контакту работают.
5. Проверьте, что webhook доступен извне по `GET /api/max/webhook`; его конфигурация требует секретов, переданных вне Git.
