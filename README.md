# Buxme AI-Scout

Мини-приложение для менеджера Buxme в MAX: поиск компаний по региону и объяснимая AI-оценка потенциальных B2B-клиентов. Приоритетный сценарий: открыть бота, запустить Mini App, ввести код сотрудника и регион, просмотреть компании и карточку выбранной организации.

- Бот: https://max.ru/t519_hakaton_max_bot
- Mini App: https://bux-me-bot.vercel.app/
- Код: этот репозиторий; для конкурсной сдачи укажите конкретный commit hash.

## Состояние функций

| Функция | Режим и источник |
| --- | --- |
| Поиск компаний | В `live`: серверный `POST /api/scout/search`. Источник бэкенда выбирается через `SCOUT_DATA_SOURCE`: текущий Rusprofile или датированный снимок 50 реальных компаний из 17 регионов. В `mock`: четыре синтетические карточки. Режим сайта задаёт `VITE_APP_MODE` при сборке. |
| AI Score | В серверном поиске: вывод GigaChat по полученным данным компании, это оценка модели, не подтверждённый факт. |
| Вход по коду | Демонстрационный. В `live` сервер принимает код формата `BUX-2048`, но не проверяет его по базе сотрудников и не удостоверяет пользователя MAX. |
| Оффер, скрипт, пересчёт после звонка | Демонстрационные шаблоны и локальный расчёт; в интерфейсе отмечены как демо. |
| Избранное, недавние регионы, статусы | Хранятся только в браузере пользователя. |

Интеграция с MAX включает официальный Bridge и webhook для приветствия и кнопки `open_app`. Кнопка открывает тот же публичный URL, что и сайт. Административные настройки выданного бота не меняются.

## Архитектура

- `src/` — React 19, TypeScript, Vite, интерфейс и сервисы. `src/services/scout/scoutService.ts` выбирает mock или HTTP-поиск.
- `api/scout/search.py` — FastAPI-маршрут поиска; преобразует результаты парсера в контракт карточек и вызывает AI-оценку.
- `backend/parser.py` — парсер команды, запускающий Playwright/Chromium. Корневой `parser.py` — отдельный исходный скрипт команды.
- `backend/gigachat.py` — OAuth и запрос к GigaChat. Ключ хранится только на сервере.
- `api/max/webhook.py`, `server/` — webhook и клиент MAX Bot API.
- `api/auth/max.py` — демонстрационный вход по коду.

Парсер получает компании из Rusprofile. Снимок в `backend/data/rusprofile_snapshot.json` собран 28 сентября 2026 года тем же парсером для резервной проверки в облаке, где Rusprofile отвечает HTTP 403. Он содержит только названия, ИНН, регионы, отрасли и ссылки; это неполная выборка, которая не обновляется автоматически. Выбор региона фильтрует полученный набор; отсутствие результата не означает отсутствия компаний в регионе. Поля следует перепроверять в первоисточнике. Другие источники, обещанные в исходной концепции, ещё не подключены.

## Запуск через Docker

Нужны Docker и Docker Compose. Скопируйте `.env.example` в `.env` и заполните серверные секреты. Затем выполните одну команду:

```bash
docker compose up --build
```

Сайт: `http://localhost:8080`. Nginx направляет `/api/scout/*` и `/api/auth/*` в Python-контейнер на внутреннем порту 8000. Для локального демо без GigaChat поставьте `VITE_APP_MODE=mock` в аргументах сборки frontend или используйте `pnpm dev` с таким значением в локальном `.env`. Docker-сборка по умолчанию рассчитана на live-поиск и требует ключ GigaChat. Первоначальная загрузка базовых образов и Chromium в лимит времени сборки не входит.

Остановка: `docker compose down`. Повторный запуск: `docker compose up --build`.

## Переменные окружения

Смотрите `.env.example`. `VITE_*` попадают в браузерную сборку; `BOT_TOKEN`, `MAX_WEBHOOK_SECRET` и `GIGACHAT_API_KEY` должны храниться только на сервере. Ключ GigaChat — Base64-значение для заголовка `Authorization: Basic`, выданное разработчиками сервиса. `GIGACHAT_SCOPE` должен соответствовать типу доступа (`GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`). Модель задаётся `GIGACHAT_MODEL`; по умолчанию `GigaChat-2`.

Для Vercel переменные задаются в Project Settings → Environment Variables. После их изменения нужна новая production-сборка, поскольку `VITE_APP_MODE` встраивается во frontend при сборке. Публикуйте с `VITE_APP_MODE=live` только после успешной проверки серверного поиска. Без `SCOUT_BACKEND_URL` и `GIGACHAT_API_KEY` поиск возвращает HTTP 503 с сообщением о ненастроенном AI-поиске.

`SCOUT_DATA_SOURCE=rusprofile` запускает существующий парсер, а при его ошибке переходит на снимок. `SCOUT_DATA_SOURCE=snapshot` сразу использует снимок: так настроен Render, поскольку Rusprofile возвращает ему HTTP 403. Ответ API сообщает `mode: snapshot` и `sourceDate`; сайт показывает эту дату и ограниченный охват. GigaChat оценивает компании из снимка при каждом поиске.

Серверный Playwright требует Chromium и системные библиотеки. Docker-образ устанавливает их. В среде Vercel отсутствуют нужные системные библиотеки для Chromium, поэтому `render.yaml` описывает отдельный Docker-бэкенд на Render. После его развёртывания задайте публичный HTTPS-адрес сервиса в серверной переменной Vercel `SCOUT_BACKEND_URL`. Маршрут Vercel `/api/scout/search` передаст запрос этому бэкенду. Ключ GigaChat задаётся только как секрет Render; не публикуйте его в `VITE_*`.

Бесплатный сервис Render ограничен 512 МБ памяти и засыпает после 15 минут простоя. Первый запрос после паузы может запускаться около минуты. Для конкурсной проверки доступность и время первого ответа необходимо проверить в MAX; при необходимости перенести сервис на постоянно работающий тариф. Это настройка хостинга, код парсера при переносе не меняется.

## Проверка

1. Откройте бота в MAX, отправьте `/start`, нажмите «Открыть AI-Scout».
2. Введите `BUX-2048`, затем регион, например `Краснодарский край`.
3. Проверьте подпись результата: «Демо-данные», «Актуальные данные Rusprofile» или «Снимок Rusprofile» с датой.
4. Откройте карточку, проверьте источники и пометки демонстрационных действий.
5. Повторите основной сценарий в мобильном и веб-клиенте MAX. Проверка в обычном браузере не заменяет эту проверку.

Автоматические проверки:

```bash
pnpm test
pnpm typecheck
pnpm lint
pnpm build
python -m unittest discover -s tests/backend
```

## Публикация и ограничения

Vercel публикует frontend и Python Functions при успешном коммите в `main`. У владельца проекта должен быть доступ к публикации коммита в Vercel. Для публичного Mini App нужен HTTPS URL, уже привязанный организаторами к выданному боту. После публикации проверьте `GET /api/max/webhook` и `POST /api/scout/search` на production-адресе, затем проведите сценарий внутри MAX.

Пользовательский код пока не является настоящей аутентификацией. Живой парсинг зависит от внешнего сайта и может измениться; облачный адрес Render сейчас получает от Rusprofile HTTP 403, поэтому выдаёт датированный снимок. Результаты AI являются рекомендацией, а не официальными данными. Рабочие токены и ключи отсутствуют в репозитории. Описание продуктовых HTTP-методов находится в `DATA-API.yaml`; тестовые доступы для внешней проверки нужно передать организаторам предусмотренным ими способом.
